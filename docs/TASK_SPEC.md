# Постановка кейса: Оперативный мониторинг гидрологической динамики по совместным данным Sentinel-1 (SAR) и Sentinel-2 (MSI)

> **КосмоХакатон 2026** · Федеральный проект «Кадры для космоса»  
> Источник: `docs/Постановка_кейса_-_Гидрологический_мониторинг_КосмоХакатон_2026.pdf`

---

## 1. Краткое содержание задачи

Разработать комплекс, который по паре разновременных спутниковых наблюдений определяет положение водной поверхности и выделяет зону нового затопления - и продолжает работать при сплошной облачности, когда оптическая съёмка непригодна.

На вход должны подаваться снимки Sentinel-1 и Sentinel-2, чтобы на выходе получить три площади в гектарах:
1. Зона нового затопления (`flood_ha`);
2. Водное зеркало на дату «до» (`water_pre_ha`);
3. Водное зеркало на дату пика (`water_peak_ha`).

### Усложнения задачи:
- Часть воды на SAR выглядит как суша (ветровая рябь, затопленный лес с double-bounce);
- Часть суши выглядит как вода (гладкий асфальт, ВПП, радиотени рельефа/зданий);
- Оптика в паводок часто закрыта сплошной облачностью или показывает мутную воду (где NDWI падает ниже 0);
- Доля затопления составляет доли процента от площади района $\to$ высокий риск ложных срабатываний.

## 2. Полное описание задачи и проблематика

Мониторинг гидрологических рисков (половодий, дождевых паводков, заторных подъёмов уровня, изменения береговой линии) требует одновременно оперативности и независимости от погоды:
- Паводковый фронт проходит в циклональную погоду при сплошной облачности (оптика Sentinel-2 непригодна, безоблачные сцены появляются уже после спада воды);
- Радиолокация Sentinel-1 всепогодна, но неоднозначна в интерпретации;
- Съёмки Sentinel-1 и Sentinel-2 не синхронизированы: разрыв от нескольких часов до 5 суток, тогда как на пике паводка урез воды смещается за часы;
- Неоднородность архива: для части исторических событий пара «до/после» разнесена на 2 недели и более.

### Что разрабатывает команда (комплект из 5 элементов):
1. **Модуль сегментации водных объектов**: совместная обработка радиолокационного и оптического каналов; бинарные маски водной поверхности по AOI на дату «до» и пик (`water_pre`, `water_peak`).
2. **Модуль пространственно-временного анализа**: сравнение «до» и «пик»; маска нового затопления (`flood` = вода на пике, которой не было до и не постоянная) и маска убыли (`receded`).
3. **Файл с результатами работы**: `submission.csv` с площадями + растровые маски `predictions/<pair_id>_flood.tif`.
4. **Интерактивная карта и автоматический сводный отчёт**: площади в га и км², доля затопления, распределение по типам покрова.
5. **Репозиторий, аналитический отчёт и презентация**.

### Продуктовая цель:
Прототип аналитического слоя для регионального контура мониторинга рисков МЧС / бассейновых управлений:
- Непрерывное обновление по каждому новому пролету SAR без ожидания оптики;
- Отслеживание динамики уреза воды между сезонами и годами;
- Наличие REST API для программного доступа.

## 3. Теоретический раздел и глоссарий

| Термин | Значение в рамках соревнования |
|---|---|
| **ДЗЗ** | Дистанционное зондирование Земли. |
| **SAR** | Радиолокатор с синтезированной апертурой (активная всепогодная съемка). |
| **MSI** | Multispectral Instrument (оптический сенсор Sentinel-2). |
| **$\sigma^0$ (сигма-ноль)** | Удельная эффективная площадь рассеяния в дБ. |
| **VV / VH** | Поляризации сигнала: сонаправленная (VV) и кросс-поляризация (VH). |
| **GRD / IW** | Ground Range Detected / Interferometric Wide swath (полоса 250 км, разрешение ~10 м). |
| **Спекл** | Зернистый мультипликативный когерентный шум интерференции. |
| **Double-bounce** | Двойное отражение: вода $\to$ вертикальный ствол дерева/тростник $\to$ антенна. Аномально высокий $\sigma^0$ подтопленной растительности. |
| **Радиотень** | Экранирование лучом склона рельефа или высоких зданий. Ложно низкий $\sigma^0$. |
| **Layover / foreshortening** | Геометрические искажения на крутых склонах. |
| **Локальный угол падения** | Угол между лучом радара и нормалью к рельефу. Влияет на $\sigma^0$. |
| **Восходящая / нисходящая орбита** | Направление витка; с разных орбит геометрия теней несопоставима. |
| **L2A / SR, SCL** | Данные Sentinel-2 с атмосферной коррекцией и маской Scene Classification Layer. |
| **NDWI** | $(B03 - B08) / (B03 + B08)$ - зеленый и NIR. |
| **MNDWI** | $(B03 - B11) / (B03 + B11)$ - зеленый и SWIR (1610 нм), подавляет застройку. |
| **AWEI** | Automated Water Extraction Index - многоканальный индекс, устойчивый к теням. |
| **HAND** | Height Above Nearest Drainage - высота точки над ближайшим дренажом/водотоком по линии стока. |
| **Водное зеркало** | Открытая водная поверхность, наблюдаемая сверху. Затопленная растительность водным зеркалом не считается. |
| **Постоянная вода** | Водная поверхность круглый год по архиву JRC Global Surface Water (occurrence $\ge 80\%$). |

## 4. Физика сенсоров и гидрологический контекст

### Как радиолокатор видит воду
- Спокойная вода гладкая относительно $\lambda \approx 5.6$ см $\to$ зеркальное отражение $\to$ низкий $\sigma^0$ (темный тон). Гистограмма бимодальна $\to$ базовый порог Оцу на VV.
- Нарушения:
  1. Ветровая рябь (ветер $>3\text{-}4$ м/с) $\to \sigma^0$ растет $\to$ пропуск воды;
  2. Затопленный лес $\to$ double-bounce $\to \sigma^0$ аномально высокий $\to$ пропуск воды;
  3. Сухой гладкий асфальт, бетон, песок $\to$ зеркальное отражение $\to$ ложная вода;
  4. Радиотени от рельефа/строений $\to \sigma^0 \approx$ шум $\to$ ложная вода.

### Как оптический сенсор видит воду
- Вода сильно поглощает NIR и SWIR при отражении в зеленом (NDWI, MNDWI $>0$).
- Систематическая ошибка: мутная паводковая вода со взвесью поднимает отражение в Red и NIR $\to$ NDWI падает ниже нуля $\to$ пропуск паводковых вод. Требуются MNDWI и AWEIsh.

### Гидрологические барьеры
1. **HAND**: ориентир 15-20 м для равнинных рек умеренного пояса. Выше - затопление физически невозможно.
2. **Уклон**: на склонах $>5\text{-}10^\circ$ сплошного затопления не бывает.
3. **Гидрографическая связность**: затопление примыкает к руслу, изолированные ямы на водоразделах - ложные срабатывания.
4. **Маска постоянных вод GSW**: отделяет постоянное русло от паводкового разлива.

## 5. Определение классов в эталоне

Пятиканальная маска:
- `water_pre`, `water_peak`: открытая водная поверхность на дату «до» и пик;
- `permanent`: постоянная вода по архиву JRC GSW (occurrence $\ge 80\%$), исключается из `flood`;
- `flood`: вода на пике, которой не было «до» и не постоянная;
- `receded`: вода, ушедшая между датами (спад).

> Затопленная растительность в открытую маску воды не включается, но в сервисе учитывается отдельным продуктовым слоем.

## 6. Состав выданного набора данных

- Сетка: **10 м**, проекция **EPSG:32652**, растры от $3000 \times 3000$ до $4500 \times 4500$ пикселей (площадь 900-1650 км²).
- Выборка: **8 пар событий** (в зачете) + **3 пары межени** (контроль ложных тревог).

### Файловая структура:
- `vectors/`: границы Амурской области, полигоны AOI, гидросеть OSM, бассейны HydroSHEDS;
- `tables/`: реестр событий, каталог сцен, даты «до» и «пик»;
- `rasters/<event>/<aoi>/`:
  - `S1_pre.tif`, `S1_peak.tif` (VV, VH, VV/VH в дБ);
  - `SENTINEL2_pre.tif`, `SENTINEL2_peak.tif` (B3, B4, B8, B11, NDWI, MNDWI, NDVI, AWEIsh);
  - `AUX_terrain_gsw.tif` (каналы: slope, hand, occurrence, seasonality, max_extent, builtup);
  - посуточный ряд ERA5;
- `reference_masks/`: эталонные 5-канальные маски;
- `sample_submission.csv`: шаблон сабмита.

### Правила формирования эталонной разметки организаторов:
1. SAR: порог VV по Оцу в $[-22, -12]$ дБ, фильтрация спекла, падение рассеяния $\ge 3$ дБ на пике;
2. Оптика: MNDWI $>0.1$, NDWI $>0.15$, NDVI $\le 0.2$, AWEIsh $>0$;
3. Фильтры: slope $\le 5^\circ$, HAND $\le 25$ м, исключение builtup, постоянная вода GSW occurrence $\ge 80\%$, MMU $\ge 25$ пикселей (0.25 га);
4. Консенсус источников.

## 7. Формат сабмита и требования

### Структура `submission.csv`:
```csv
pair_id,flood_ha,water_pre_ha,water_peak_ha
flood_2019_07_amur__belogorsk,187.19,694.27,869.26
...
```
- Перечень пар строго совпадает с `sample_submission.csv`;
- Площади неотрицательны, не превышают площадь района, в гектарах с округлением до сотых;
- $flood\_ha \le water\_peak\_ha$;
- Без пропусков и NaN.

### Растры масок в `predictions/`:
- Файлы `<pair_id>_flood.tif`;
- GeoTIFF uint8 (только 0 и 1);
- Размер, аффинная трансформация и CRS (EPSG:32652) совпадают с входными растрами;
- **Расхождение площадей по растру и в CSV не должно превышать 2%**.

## 8. Официальная метрика оценки

$$\text{Score} = 0.45 \cdot Q_{\text{flood}} + 0.25 \cdot Q_{\text{water\_peak}} + 0.15 \cdot Q_{\text{water\_pre}} + 0.15 \cdot \text{Spec}_{\text{base}}$$

- По парам событий:
  $$q = \max\left(0, 1 - \frac{|X_{\text{сабмита}} - X_{\text{эталона}}|}{\max(X_{\text{эталона}}, \text{порог})}\right)$$
  - Порог для затопления: **50 га**;
  - Порог для водного зеркала: **200 га**.
- По контрольным парам межени:
  $$\text{доля} = \frac{\max(0, flood_{\text{сабмита}} - flood_{\text{эталона}})}{\text{площадь\_района}}$$
  $$\text{Spec}_{\text{base}} = \text{mean}\left(1 - \min\left(1, \frac{\text{доля}}{0.005}\right)\right)$$
  (допуск $0.5\%$ от площади AOI).

## 9. Требования к программному сервису, отчёту и защите

### Сервис:
- Запуск одной командой (Docker / `docker compose` / локально);
- Прием запроса по полигону / bbox и датам «до»/«после»;
- Интерактивная карта (слои «до», пик, паводок);
- Выгрузка векторов GeoJSON/Shapefile с атрибутами (ID контура, тип, площадь);
- Автосводка отчета (га, км², распределение по покрову built-up/сельхоз);
- REST API для автоматизации;
- Инкрементальное обновление при поступлении новых витков SAR.

### Структура `REPORT.md` (8 разделов):
1. Краткое описание задачи и протокола оценки;
2. EDA и наблюдения по данным (доля воды, поляризации, разрыв дат S1/S2);
3. Оценка существующих подходов и их ограничений;
4. Подход и модель (пайплайн, слияние каналов, валидация);
5. Эксперименты и сравнения (абляции 4 стадий, честные метрики);
6. Инженерные и предметные решения (спекл, углы падения, затопленный лес, MMU);
7. Итоговое решение;
8. Выводы и дальнейшее развитие.

### Презентация (`SLIDES.md`):
- 8-12 слайдов;
- Отражение постановки, схем модулей, результатов метрик, демонстрации сервиса, физических лимитов и слабых мест.
