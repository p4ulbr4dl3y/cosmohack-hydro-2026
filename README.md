# HydroWatch Amur: Оперативный спутниковый мониторинг паводков и гидрологической динамики по Sentinel-1 и Sentinel-2

Автономный геоинформационный комплекс оперативного картирования зон затопления, ретроспективного анализа и динамики водного зеркала в бассейне Верхнего и Среднего Амура (Амурская область, 11 пар «район интереса × событие»).

> **КосмоХакатон 2026** · Кейс **Гидрологический мониторинг** · Команда **Dreamteam 4.0**

## Быстрый запуск в 1 команду

### Вариант 1. Запуск через Docker Compose (рекомендуемый для жюри)

Развертывание сервиса единым контейнером без локальной настройки зависимостей:

```bash
docker compose up --build
```

Сервис готов к работе по адресам:
- `http://localhost:8000/` - интерактивная карта с послойным просмотром (`flood`, `water_pre`, `water_peak`), аналитическими карточками и диаграммой ESA WorldCover;
- `http://localhost:8000/docs` - интерактивный Swagger UI для вызова REST API эндпоинтов.

Остановка контейнера:
```bash
docker compose down
```

---

### Вариант 2. Локальный запуск через `uv`

```bash
# 1. Синхронизация окружения (Python >= 3.13)
uv sync

# 2. Запуск асинхронного сервиса
uv run uvicorn src.service.app:app --host 0.0.0.0 --port 8000
```

---

### Вариант 3. Воспроизведение метрик и CLI-команды

Все эталонные маски (`hydrowatch_amur/reference_masks/`) и сгенерированные предикты (`predictions/`) включены в репозиторий. Проверка официального Score работает сразу офлайн:

```bash
# 1. Расчет официального соревновательного Score и 4-стадийных абляций
uv run python -m src.cli evaluate --run-ablations

# 2. Пространственный hold-out (leave-one-AOI-out диагностика)
uv run python -m src.cli evaluate --holdout

# 3. Генерация аналитического отчета по паре AOI
uv run python -m src.cli report --pair-id flood_2019_07_amur__blagoveshchensk

# 4. Запуск полного набора автотестов (236 backend + 119 frontend тестов)
uv run pytest
npm test --prefix frontend -- --run
```

## 4. Спецификация REST API

Сервис предоставляет программный интерфейс для интеграции с внешними геопорталами и ситуационными центрами:

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/api/v1/health` | Проверка доступности сервиса и количества доступных пар |
| `GET` | `/api/v1/pairs` | Реестр 11 пар с датами съемок, орбитами и площадями районов |
| `GET` | `/api/v1/report/{pair_id}` | Сводка площадей и распределение затопления по угодьям (WorldCover) |
| `GET` | `/api/v1/report/{pair_id}/csv` | Экспорт аналитической гидрологической справки в CSV |
| `GET` | `/api/v1/geojson/{pair_id}` | Векторные контуры слоев (`flood`, `water_pre`, `water_peak`) в EPSG:4326 |
| `POST` | `/api/v1/predict` | Расчет зон затопления по полигону или ограничивающему прямоугольнику |
| `GET` | `/api/v1/geotiff/{pair_id}` | Скачивание растровых GeoTIFF масок |
| `GET` | `/api/v1/shapefile/{pair_id}` | Экспорт векторных контуров в архиве ESRI Shapefile |

## 5. Воспроизводимость и статус данных

### Работа офлайн:
- в репозитории **полностью автономно и офлайн** работают: веб-сервис, интерактивная карта, Swagger API, расчет официальной метрики (`evaluate`), hold-out валидация, отслеживание динамики и готовые маски предсказаний (`predictions/`);
- алгоритм не содержит случайных состояний (детерминирован) и выполняется на CPU без использования GPU.

### Исходные радары Sentinel-1 (~2.9 ГБ):
- радарные сцены `S1_pre_*.tif` и `S1_peak_*.tif` не включены в git-репозиторий из-за стандартных ограничений GitHub на размер репозитория и условий распространения данных;
- при необходимости пересчитать инференс всех сцен с нуля радары скачиваются в одну команду:
  ```bash
  uv run python -m src.cli fetch
  ```
- после однократной загрузки полный пайплайн инференса (`uv run python -m src.cli predict`) выполняется полностью локально.

## 6. Ресурсоемкость и производительность

Измерения проведены на стандартном процессоре без использования GPU:
- среднее время обработки одной пары AOI (1200-1650 км²): **7.92 секунды**;
- суммарное время инференса всех 11 пар: **87.12 секунды**;
- пиковое потребление оперативной памяти: **~3.5 ГБ**;
- чтение SAR каналов оптимизировано полосами через оконный интерфейс `rasterio.windows.Window` (1024 строки), рабочий объем чтения ограничен одним блоком;
- отрисовка векторных слоев на карте переведена на аппаратный HTML5 2D Canvas (`L.canvas`), что исключает просадки FPS при отображении более 1000 контуров.

Полные технические доказательства, физическое обоснование и анализ эталона изложены в [REPORT.md](REPORT.md).
